# AI_LOG

Весь код у цьому репозиторії згенерував Claude Code за моїми запитами; нижче — чесний журнал цієї роботи.

## Ключові промпти
1. «Виконай цю задачу (test-task-room-booking.md) одним файлом на Python FastAPI» → `main.py`, тести, Docker.
2. «Додавай окремі файли, міграції і додаткові завдання» → runner міграцій, повтори/статистика/Idempotency-Key, CI, `.claude/`, документація.
3. «Зроби це все ти» → git-історія осмисленими комітами, фіналізація цього логу.

## Де AI помилився
- Тест статистики бронював 14:00–20:00 (6 год), хоча максимум 4 год. Запит повертав `400`, тест падав
  з `KeyError: 'id'`. Помітили при першому прогоні тестів, виправлено дані тесту.
- Перший прогін ruff показав `B904` і задовгі SQL-рядки. Свідомо вимкнено B904 (переклад помилок БД в `ApiError`)
  та E501 для `main.py`, а не переписано механічно.
- Початкову версію зробили без міграцій (схема створювалась на старті через `CREATE IF NOT EXISTS`),
  що суперечить вимозі завдання; виправлено окремим кроком (`migrations/` + runner).
- Початково був лише `main.py` без `CLAUDE.md`, `PLAN.md`, README — також додано пізніше.

## Що переписано вручну
Нічого: код не переписувався людиною, тільки ревʼюїлось і запускалось. Перед захистом варто самому
пройтись по `validate_slot`, `free_intervals`, `create_booking` і зуміти пояснити кожен рядок.

## Рішення, яке я б не прийняв без пояснення
- Кешування результатів ідемпотентності для невдалих запитів: тимчасовий `409` «залип» би назавжди.
  Тому зберігаються лише успішні (`201`) відповіді.
- Перевірка перетину через SELECT → INSERT або in-memory lock: ламається при двох інстансах.
  Захист — `EXCLUDE`-constraint у Postgres, а тест на 16 паралельних запитів це доводить.
